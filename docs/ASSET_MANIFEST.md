# Asset manifest

Required by v2 §3 and decision 6. One row per asset: status, where it is, its sha256, how many records, its licence, and what validation found. A missing file is written `missing`; it is never confused with a missing result.

- Audit date: 4 October 2026. Nothing listed here was modified.
- `data/cache/` is a download cache for importers and audits, ignored by git (`.gitignore`: `data/cache/`).
- Status: `available` (present and parsed), `missing` (not obtainable from the named source), `invalid` (present but unusable as is).

## 2. Quran corpus

### 2.1 Structure

A JSON array of 6,236 objects. `ayah_id` runs 1–6236 without gaps; `(surah_no, ayah_no_surah)` is unique; 114 surahs; `place_of_revelation` Meccan 4,613 / Medinan 1,623.

Fields on every record: `ayah_id`, `surah_no`, `ayah_no_surah`, `text_ar`, `text_en`, `surah_name_ar`, `surah_name_en`, `place_of_revelation`, `arabic_annotation`, `has_annotation`, `annotation_source_file`. 6,229 records also carry `annotation_timestamp`, `annotation_model` (`gpt-4o-mini`) and `processing_method` (`batch_api`); the other 7 (ids 401, 2075, 2293, 2727, 4187, 4732, 6010) carry `manually_fixed` and `fix_applied_at` instead.

`arabic_annotation` has seven stable keys on all 6,236 records: `islamic_cognitive_dimension` (`islamic_domain`, `sub_topics`), `related_sciences` (eleven groups of free-text fields), `related_research_fields[]`, `categories[]`, `search_retrieval_fields` (`key_concepts`, `keywords_ar`, `keywords_en`, `related_verses`, `context_window`), `semantic_tags_entities` (`semantic_tags`, `named_entities` with `divine_names`, `events`, `locations`, `persons`, `religious_texts`), `application_fields` (`difficulty_level`, `emotional_tone`, `sentiment_score`, `urgency_level`, `use_cases`).

Schema drift the importer must absorb: `sub_topics` is a string in 61 records; `sentiment_score` is a string in 165; `related_verses` mixes integers (1,782) and strings (27,980); key typos (`islamic_thology` ×23, `cultural_antropology` ×3, `commercial_claw` ×1); `islamic_domain` has a misspelt value `qsas` (299) beside `qasas` (787) and 13 Arabic values. 292 records have extra top-level annotation keys, and in 318 records an annotation string repeats the verse text verbatim (the model echoed it). **Whitelist the seven keys and never read scripture from an annotation.**

`text_en` looks like a modern copyrighted translation (bracketed glosses such as `˹of Jerusalem˺`); its source and licence are unknown, so it is not displayable until identified.

### 2.3 Provenance

`text_ar` equals the `ayah_ar` column of `The Quran Dataset.csv` in the same folder for all 6,236 verses, and equals alquran.cloud's `quran-uthmani` edition for 6,125 verses. The remaining 111 differ only because the corpus removed a leading U+FEFF from 1:1 and the standard basmala prefix from verse 1 of 110 surahs. In 95:1 and 97:1 the prefix is spelt `بِّسْمِ` (with shadda), the stripping missed it, and the corpus verse text begins with the basmala:

- 95:1 `بِّسْمِ ٱللَّهِ ٱلرَّحْمَٰنِ ٱلرَّحِيمِ وَٱلتِّينِ وَٱلزَّيْتُونِ`
- 97:1 `بِّسْمِ ٱللَّهِ ٱلرَّحْمَٰنِ ٱلرَّحِيمِ إِنَّآ أَنزَلْنَٰهُ فِى لَيْلَةِ ٱلْقَدْرِ`

### 2.4 Against the old demo's "Tanzil" file

`ara-quranuthmanihaf` is the King Fahd Complex Hafs text (version 13), not Tanzil. Only 27 corpus verses are byte-identical. The differences are mostly encoding conventions: sukun U+06E1 vs U+0652 (33,621 replacements), open tanween U+08F0–08F2, decomposed hamza, final yeh U+064A vs U+0649, shadda placement on assimilated letters, stop marks without a preceding space. After normalisation and folding of those conventions, 275 verses still differ in letters. This file is a valid reference for the King Fahd script (v2 §10 names it as an acceptable source) but must not be labelled Tanzil.

### 2.5 Owner decisions needed before import

1. Which text is displayed: the corpus `text_ar` (pre-2021 Tanzil with extra tajweed meems), Tanzil 1.1 verbatim, or the King Fahd text. The rule "never fix scripture" forbids patching the corpus; choosing a reference is an owner decision.
2. 95:1 and 97:1: the corpus verse text includes the basmala, unlike the other 110 surahs.
3. Tanzil's terms require verbatim copies and keeping its notice; the corpus is not a verbatim copy of any Tanzil version (basmala and BOM removed).

## 3. Hadith books (fawazahmed0 `hadith-api`, Arabic editions)

## 4. `processed_sunnah_data.json`

### 4.1 Structure

`{"metadata": {...}, "results": [...]}`. Metadata: 3,920 processed, model `gpt-5-mini-2025-08-07`, last update 2025-11-12. Each result has `id` (string), `original_text`, `modern_rephrase`, `summary`, `domain`, `category_old`, `category_new`, `subcategory`, `possible_theories`, `relevant_fields`, `potential_applications`, `semantic_tags`, `key_concepts`, `topics_for_retrieval`, `sciences` (object); 6 records also have `processing_error: "Text too short or empty"` (ids 617, 1783, 1824, 2737, 5177, 20593). Ids are unique: 1–3921 without 1583, 1911, 2081, 2336, 2802, plus 4020, 5177, 19027, 20593. `domain` has 12 main values and a few model-invented ones; `category_new` has 852 distinct values.

`original_text` is an abridged narration with the compiler's codes, e.g. `(ق) عَنِ ابْنِ عُمَرَ … [خ 8، م 16]`: a leading code (`ق` agreed upon, `خ`, `م`…) and bracketed references (`خ` Bukhari, `م` Muslim, `د` Abu Dawud, `ت` Tirmidhi, `ن` Nasa'i, `جه` Ibn Majah, `ط` Malik, `حم` Ahmad, `مي` Darimi, `هق`, `ك`, `حب`).

### 4.2 cp720 repair

`s.encode("cp720").decode("utf-8")` was applied to every string value (keys are ASCII):

- 288,066 strings; **0 failures**; 59,893 unchanged (pure ASCII).
- Round trip `repaired.encode("utf-8").decode("cp720") == original` holds for all 288,066.
- Re-encoding every repaired string and serialising with `json.dumps(…, ensure_ascii=False, indent=2)` reproduces the original file **byte for byte** (73,589,249 bytes).
- Repaired text is Arabic (12.5 M characters) and ASCII (2.2 M), plus `ﷺ` (5,488), «» quotes, dashes, and a few Cyrillic/Greek/CJK characters that came from the model's output, not from the repair.

### 4.3 Mapping to the hadith books

Method (matching only, never display): drop the leading code, take the main narration (before `!` or «وفي رواية»), drop the references and footnote markers, normalise both sides (no diacritics, one alef, `ى→ي`, `ة→ه`, hamza seats folded, `ﷺ` expanded), and score each book hadith by IDF-weighted coverage of the record's word 3-grams. A record matches a book when coverage ≥ 0.5. The result for every id is in `data/cache/sunnah-nine-books-map.json` (best hadith per book, coverage, and the parsed references).

## 5. Reranker reference (`cross_encoder_reranker.py`)

1. Model: `amberoad/bert-multilingual-passage-reranking-msmarco` (Transformers sequence classifier, max 512 tokens, sigmoid or softmax score); falls back to a neutral 0.5 if the model fails to load.
2. Pairs: (query, context) where the context is built from the **enriched fields**, not the hadith text: `summary` (or the first 500 characters of `modern_rephrase`), five `semantic_tags`, three `key_concepts`, `category_new`, `subcategory`, two `topics_for_retrieval`.
3. Metadata boost: token overlap between the normalised query and ten enriched fields, weighted (`semantic_tags` 0.25, `key_concepts` 0.20, `topics_for_retrieval` 0.15, `summary` 0.10, `category_new` 0.08, `subcategory` 0.07, `domain` 0.05, `relevant_fields` 0.05, `sciences` 0.03, `potential_applications` 0.02), +50 % on an exact phrase hit, capped at 1.
4. Score: `0.6 × (0.7 × cross_encoder + 0.3 × metadata) + 0.4 × first-stage score`, sorted descending, optional top-k.
5. A `MetadataOnlyReranker` variant skips the model and uses light Arabic stemming with its own weights.
